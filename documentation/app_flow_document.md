# Habit Record Fullstack App Flow Document

## Onboarding and Sign-In/Sign-Up
A brand-new user arrives at the application by visiting the root URL. If the user is not signed in, the landing page displays a welcoming interface with options to sign up or sign in. The user can choose to create an account by clicking the sign-up button, which brings up a form asking for an email address and a password. This form is powered by Better Auth and validates that the email is formatted correctly and the password meets length requirements. Once the user submits valid information, Better Auth creates a new user record, sends a confirmation email if configured, and establishes a session. After successful sign-up, the user is automatically redirected to the dashboard. To sign in, the user returns to the root URL or clicks the sign-in link, enters their registered email and password, and submits the form. Better Auth validates the credentials, and on success, redirects the user to the protected dashboard area. If the user forgets their password, they can click the “Forgot Password” link on the sign-in form. This triggers an email with a password reset link. The user follows that link, sets a new password in a secure form, and is automatically signed in upon completion. At any time, the user can sign out by clicking the sign-out option in the header or sidebar, which clears the session and returns the user to the landing page.

## Main Dashboard or Home Page
After signing in, the user lands on the main dashboard. The top of the page features a header displaying the application logo, the current user’s avatar or initials, and a sign-out control. Along the left edge, a vertical sidebar offers navigation links to key sections such as Dashboard, Statistics, and Settings. In the main content area, the user sees an interactive area chart that visualizes habit completion over time, followed by a sortable data table listing the user’s habits. Each row in the table shows the habit name, scheduled frequency, current streak, and an action button for logging today’s completion. The page is styled with Tailwind CSS and supports both light and dark mode based on the user’s preference. Users can click on the sidebar links to navigate to other sections, and the chart and table update automatically whenever the user logs new data or navigates back to the dashboard.

## Detailed Feature Flows and Page Transitions
When the user wants to create a new habit, they click the “New Habit” button in the dashboard header. This opens a dialog box where the user enters the habit name and selects a frequency such as daily or weekly. After the user submits the form, a Server Action sends a request to the `/api/habits` endpoint. The server validates the user session, writes the new habit into the PostgreSQL database via Drizzle ORM, and returns the created habit object. The dialog closes and the data table refreshes to display the new habit. To log a habit completion, the user clicks the “Log” button in the habit’s row. This triggers a Server Action that calls `/api/habits/[id]/completions`, where the server checks that the habit belongs to the current user and inserts a record with the current date into the completions table. On success, the button changes color and the streak count updates immediately in the table. If the user wishes to edit or delete an existing habit, they hover over the habit row and click the edit icon or delete icon. The edit action opens a similar dialog prefilled with the habit’s details. After making changes and submitting, the server updates the record and the table reflects the changes without requiring a full page reload. Deleting prompts a confirmation within a dialog, and upon confirmation, the server removes the record and the table row disappears. The interactive chart at the top of the dashboard always fetches fresh data from the server when the user performs actions that affect completions, ensuring the visual streak tracker stays in sync. At any point, the user can click the Statistics link in the sidebar to see more detailed analytics, which transitions to a dedicated statistics page that uses the same chart component with different time scales.

## Settings and Account Management
The Settings section is accessible from the sidebar. On the settings page, the user finds their profile information including email and display name. They can update the display name or email in a form that, upon submission, calls an API route to update the user record. If the user changes their email, Better Auth may require email confirmation before the new address becomes active. Below the profile form, a theme toggle switch allows the user to switch between light and dark mode, with the choice persisted in local storage so it applies on future visits. The settings page also provides a link to change the password, which opens a form requiring the current password and a new password. Once the password change is confirmed by the server, the session remains active with updated credentials. A sign-out button at the bottom of Settings logs the user out and returns them to the landing page. At any time, navigation back to the dashboard is possible by clicking the Dashboard link in the sidebar or the application logo in the header.

## Error States and Alternate Paths
If the user enters an incorrect email or password on the sign-in form, an inline error message appears explaining that the credentials are invalid. During sign-up, if the email is already in use or the password is too short, the form highlights the specific field with an error message. If the user attempts to log a habit completion twice on the same day, the server returns a validation error and the UI displays a friendly notification that today’s completion has already been recorded. If the user loses internet connectivity while interacting with the dashboard, a banner at the top informs them that they are offline and queues actions locally until the connection is restored. Should the server be unavailable, each API call returns a generic error message and the UI prompts the user to retry. When the user tries to access a protected page without a valid session, they are automatically redirected to the sign-in page. If a user attempts to edit or delete a habit that does not belong to their account, the server responds with an unauthorized error and the UI displays an alert indicating that the action is not permitted.

## Conclusion and Overall App Journey
From the first visit to daily habit tracking, the user experience flows seamlessly. A new user signs up with email and password, confirms their account, and arrives at a clean dashboard displaying an interactive chart and a list of habits. They add new habits through a simple dialog, log completions with a single click, and immediately see their streak update both in the table and on the chart. The user can manage their account settings, update their profile, change their password, and switch themes without losing context. Throughout the app, error states guide the user back to normal flow, ensuring that actions like duplicate logging or invalid inputs are handled gracefully. In everyday use, the user’s main goal—tracking habits over time—is supported by a responsive interface, secure authentication, and real-time data updates, creating a straightforward yet powerful habit-tracking journey.
